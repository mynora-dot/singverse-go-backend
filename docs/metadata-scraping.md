# 歌曲元数据刮削

入口为“整理 → 歌曲信息”（`#/library/songs/metadata`）。先扫描自备媒体，使歌曲进入歌曲管理；本地文件优先采用有效的内嵌歌名和歌手，缺少任一项时才执行文件名识别，刮削用于补全或人工修正平台元数据。

## 多平台搜索响应（2026-11-19）

歌曲搜索、批次匹配与额外封面查询按平台并发请求，整体等待由最慢平台决定。每个平台的串行门、启动间隔、超时及 429 冷却继续生效；网络请求结束后按所选平台顺序串行保存候选，再去重、按相似度排序并限制返回十条。请求取消会中止平台等待与网络查询，已经取消的排队请求不会再启动平台查询。

单曲审核前端以现有搜索接口分别查询所选平台，各平台返回后立即合并显示候选，并显示实际完成数和等待中的平台。用户可提前选择和确认，确认时取消剩余查询；关闭窗口、切换歌曲也会取消旧查询。后来返回的候选不会覆盖已选候选或正在编辑的草稿，所有搜索仅产生待确认候选。批量后台仍按每首配置的间隔调度。

本机同关键词“你还要我怎样 薛之谦”单轮公开目录对照：六平台串行合计 3.489 秒，并发合计 1.613 秒，六个平台均成功。受控测试令每个平台等待 100 毫秒，总耗时由 624 毫秒降至 116 毫秒。以上为本机测试，平台响应和 NAS 出口会影响实际耗时。可用 `SINGVERSE_METADATA_SEARCH_LIVE_TEST=1 sh scripts/run-go.sh test ./internal/metadata -run '^TestLiveMetadataSearchTimings$' -count=1 -v` 记录各平台时间；测试使用临时数据库，仅查询公开歌曲元数据。

## 使用流程

1. 在顶栏“设置 → 音乐平台”（`#/system/music-platforms`）管理网易云音乐、QQ 音乐、酷狗音乐、酷我音乐、汽水音乐和咪咕音乐。新安装保留原有五个平台的默认选择，咪咕可手动启用；自动应用默认关闭，升级保留已保存的选择。平台、自动应用、相似度阈值和请求间隔在同一页保存，离页与刷新保护未保存修改。歌曲信息页显示实际设置摘要，单曲审核的“管理平台”可直达设置并返回原歌曲或批次。查询仅发送搜索关键词（通常为歌名与歌手），不上传、下载或修改媒体文件，不使用平台账号 Cookie。
2. 单曲点击“元数据刮削”：可修改关键词、选择已启用的平台重新搜索；选择候选、勾选要应用的字段，再确认写入。
3. 批量可勾选当前页歌曲后点击“刮削已选”，或在刮削页启动“刮削全部歌曲”。已应用且文件未变化的歌曲跳过，需要重新匹配时使用单曲入口。
4. 页面展示进度、待审核、失败与已应用数量，支持明细筛选、分页、暂停、继续、终止和逐项重试。批次“匹配完成”仅表示查询结束，待审核项仍需选择候选并确认。

单次选中最多 500 首；全库或指定媒体来源的批次最多 5000 首，超过上限拒绝启动，应按页分批。批次页可选择全部媒体来源或单个媒体来源；不跟随歌曲列表的来源/文件名筛选。创建指定来源批次时发送 `all=true` 和 `sourceId`，不能同时提供指定歌曲 ID。当前只展示最近批次或指定 `?batch=ID` 的批次，无批次历史列表。

## 写入与原件保护

可应用歌名、歌手、专辑、发行日期、别名、平台时长及封面。仅更新勾选且候选有值的字段，缺失值不会清空已有确认内容；每个字段记录平台、外部 ID 与确认时间。平台时长是平台提供的信息，不代表已探测本地文件。

当前正式资料保存在 `metadata_document`，旧 `song_metadata` 保留为兼容写入与迁移证据。人工订正直接修改正式字段，并保存本机决定；标签、平台自动任务和共享更新不能覆盖本机 SET/CLEAR。重新扫描或文件属性变化只重新核验相关媒体证据，不使歌名、人工订正及已保存附件整体失效。来源移除解除位置绑定，资料继续保留。完整身份、字段和附件规则见[元数据存储标准 1.0](../contracts/metadata/README.md)。

`#/library/songs` 按歌曲和版本管理；`#/library/songs/files` 保留按文件审核。标准更新接口区分 SET（包括确认相同值）、CLEAR（明确清空）和 RESET（解除本机决定）；所有读取与导出使用当前正式资料。平台参考时长、版本时间轴和文件实际时长分别保存。

自动写入默认关闭，只有明确启用并保存后，新批次才会记录启用快照。默认相似度阈值为 80%，可设为 80%～100%；排序第一的候选达到有效阈值即自动应用，同分时取服务端排序第一条。相似度由歌名与歌手字符串计算，是启发式参考，不是正确率；版本词不被抹掉，缺少歌手不会达到自动阈值，接近候选不再阻止自动写入。单曲搜索始终等待确认。关闭自动写入会阻止旧批次自动写入；提高全局阈值也会约束旧批次。

## 批次与故障

Go 单体内每次处理一首，第三方请求不占用业务数据库事务；每个平台串行且两次请求启动至少间隔 1.5 秒，连接超时 3 秒、单次 HTTP 请求超时 5 秒、JSON 响应最多 2 MB。汽水歌曲与歌手查询共用串行客户端，搜索启动至少间隔 2 秒，包含匿名凭证获取与一次失效刷新在内的总预算为 15 秒。平台变化、限流、网络故障会显示失败或部分平台警告，可换平台、修改关键词或重试；不自动绕过限制。

批次、明细、候选与配置均经 模块内嵌 SQL 持久化。保存设置会暂停运行批次；服务重启将运行批次恢复为暂停，处理中项回到等待，用户确认平台设置后继续。暂停/终止不保证撤回已经发出的网络请求，但提交前会复核状态，停止后不再自动应用该请求结果。终止保留已获取候选和已应用内容，不能续跑或重试，可新建批次。人工确认仍可审核终止批次的已有候选。

候选有效期为 7 天，过期需重新搜索；启动新批次会清理过期候选。应用时校验候选归属和文件属性，变化返回 409。旧批次应用接口在同一事务中提交字段与状态；共享单曲审核工作台的批次接口先按单曲审核幂等写入，再更新明细状态，重试相同提交标识可补齐状态。当前为单 Go 实例执行器，不支持多实例争抢同一任务。

## 封面与部署

封面走受管理员会话保护的同源代理，只接受对应平台固定 CDN 的 HTTPS URL，拒绝重定向和私有地址。平台图片默认读取原图，不再受旧的 2 MB / 4096×4096 限制，不改变像素或重新编码；可选原图或高清，加载成功显示实际像素。单次网络与缓存读取最多 32 MiB、超时 20 秒，超出时明确报读取失败，可选择高清；接受实际 JPEG/PNG/WebP。无效或不可达封面不影响已确认文本。本地上传、持久保存与 v4 分享统一支持 32 MiB 原图，最多 67,108,864 像素；展示缩略图单独生成，不重新编码正式原图。浏览器不直接加载平台封面 URL，不提供任意 URL 代理或音频地址接口。

缓存默认 `./data/metadata/covers`，可设置 `METADATA_CACHE_PATH`。它是衍生缓存，放在可写数据卷，和只读媒体目录分开；Compose 显式使用 `/data/metadata/covers` 并复用现有 Go 数据卷。缓存目前没有自动容量清理；停用平台后已缓存封面仍可显示，新下载需要功能及对应平台启用。正式原图和歌词进入 `WEBDAV_METADATA_PATH/assets/<摘要前两位>/<SHA256>.bin`；缓存清空后仍可读取正式附件。资源通过正式引用和任务租约保护，未引用资源有七天回收宽限。完整恢复须备份数据库、主密钥与持久资料目录。

SQLite/MySQL 的 `202611070001_initial_schema.sql` 直接定义原有元数据设置、任务、候选和兼容记录；`202611110001_metadata_standard.sql` 成对新增正式文档、位置、证据、合并基线、资源引用与回执，启动时分批回填旧资料。所有 `/api/v1/metadata/**` 接口受管理员会话保护，写入/搜索操作需要 CSRF；契约见 [OpenAPI](../contracts/openapi/singverse.openapi.json)。

平台适配、协议签名及解析测试参考相邻 ktv-home 项目的 MIT 实现，许可证保留于 [third-party/ktv-home-LICENSE.txt](third-party/ktv-home-LICENSE.txt)。未移植其下载、播放、外部账号 Cookie 或独立服务结构。

批量刮削可在平台设置中配置每首完成后的等待范围（默认 1～2 秒，允许 0～300 秒，含端点；最大值不得小于最小值）。设置持久化且保存时暂停活动批次，续跑使用当前间隔；等待不占用数据库连接。同一平台请求仍保持串行及至少 1.5 秒启动间隔；HTTP 429 会触发该平台至少 60 秒冷却，期间拒绝新请求，失败项可稍后手动重试。单曲搜索也受平台冷却约束，批量间隔只约束后台批次。设置为 0 秒表示不额外等待，但任务调度约每秒检查一次，同平台仍受请求启动间隔约束。随机间隔用于平滑流量，不能保证避免限流或自动化识别。

单曲元数据使用双栏审核工作台，批次候选审核复用同一组件，支持字段编辑、受管 JPEG/PNG 上传、平台封面搜索及统一确认应用。新增接口、资源备份、幂等与版本校验规则见[单曲审核](single-song-review.md)。

批量工作台已统一整体进度：total/completed 均包含跳过项，新批次持久化跳过明细，旧批次仅汇总并提示。新增批次内搜索/排序、可信度审核提示及按状态操作，自动写入改为第一候选达到有效阈值即执行；限流规则不变。接口兼容说明及统计定义见[批量工作台](batch-metadata-workbench.md)。

## 咪咕与汽水接口兼容（2026-11-19）

咪咕通过公开歌曲目录返回歌名、歌手、专辑、别名和专辑封面，不获取音频或账号 Cookie；缺少的时长、发行日期保持为空。封面按平台提供的独立地址选择最大版本，原图和高清均保留该地址，不拼接未验证的缩放参数。WebP 原始字节可代理、缓存和正式保存，本地上传仍只接受 JPEG/PNG。

汽水已改用 Go 原生匿名车机目录接口（见文末），从 `base_info`、`related_info` 与 `display_info` 提取歌曲、歌手、专辑、时长、日期和封面，数字 ID 保持字符串精度；保留 `entity.track` 与 `entity.track_wrapper.track` 的解析兼容。HTTP 200 空响应、鉴权错误和缺少结果组均显示明确失败原因，多平台请求保留其他平台候选；不把接口失败显示成无匹配结果。

本轮本地验证：`internal/metadata`、`internal/metastandard`、`internal/metastore` 测试及对应 `go vet` 通过；前端 71 项定向测试、类型检查和三个入口构建通过。全量前端 711 项中 687 项通过，24 项失败在原始提交 `059e3a14dbca545e9a66e261d8858cd2e7eda705` 的隔离副本中全部复现，涉及登录、计算服务和音频处理，本次未新增失败。新 Go 适配器真实搜索“晴天 周杰伦”返回 8 个候选，首条为周杰伦《晴天》、专辑《叶惠美》，其 WebP 封面以原始字节读取成功（800×800，91,258 字节）；同轮汽水仍返回空响应。未执行 NAS 部署或远端发布，MySQL 未配置，本轮不计 MySQL 实测。

## 汽水 Go 接入调研（2026-11-19）

当前实现采用匿名车机目录协议，由 Go 直接请求并缓存公开客户端凭证，无额外签名服务、Wine、Windows 组件或生产 Node 依赖。更新现有 Go 后端镜像即可使用，不新增环境变量、容器或数据库迁移。下表保留改造前的旧路径排查记录。

用 Go `net/http` 对“传奇 郭沁”串行发送五种真实请求，不带账号 Cookie 或签名，均为 HTTP/2、HTTP 200：

| 请求 | 返回字节 | 实际结果 |
| --- | --- | --- |
| 原 Android `/luna/search/track` | 0 | 空响应 |
| Web `/luna/pc/search/track` | 0 | 空响应 |
| Android 19.8 参数 `/luna/search/track` | 0 | 空响应 |
| Android 19.8 参数 `/luna/search/all` | 133 | `extra.empty_search=1`，没有候选组 |
| PC 参数 `/luna/pc/search/all`，未签名 | 133 | `extra.empty_search=1`，没有候选组 |

Python 补充对照中，Web 搜索增加 Origin 与 Referer 仍为 0 字节。以上只是本机当次请求结果，不代表所有地区与出口；空响应本身不能证明只差签名，也不能证明需要登录。临时诊断测试通过仅表示完成了请求和记录，不能视为汽水搜索通过验收，临时测试文件已移除。

协议参考 MIT 项目 [GSQZ/qishui-music-api](https://github.com/GSQZ/qishui-music-api/tree/924add376cadf8a2268f11999051eb976e3b8e0d)，固定提交 `924add376cadf8a2268f11999051eb976e3b8e0d`；只移植公开客户端凭证与搜索读操作，许可证随源码及 Go 容器分发，见 [LICENSE](../internal/platform/qishui/LICENSE.txt)。未移植账号、票据签名、下载或音频解析功能。此前试验的 PC 独立签名器不适合作为通用 NAS 部署方案，相关业务配置和部署文件已移除。

请求流程：

1. 进程生成 19 位匿名设备标识，通过固定 HTTPS 地址 `open.qishui.com/api/luna/v1/platform/client/token/get/` 获取 `client_token`，仅在内存中缓存。
2. 以 `access-token` 请求头向固定 HTTPS 地址 `open.douyin.com/api/luna/v1/platform/search/` 发送关键词及 `search_type=track/artist`。元数据与歌手资料共用同一实例、设备标识、凭证缓存和请求门。
3. 仅在明确的凭证失效码 `28001008` 下刷新一次；其他失败不连续重试。429 与 `Retry-After` 触发共享冷却；取消或超时的排队请求不发送。拒绝重定向、超过 2 MB、非 JSON、空响应和不完整结果结构。
4. 只取一页并按业务上限提取候选，不执行隐式分页循环。封面沿用现有固定 CDN、私网地址保护、原图画质与人工确认流程。
