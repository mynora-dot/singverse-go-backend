# 数据库初始化与验证

当前按**首次部署、从零建库**维护 SQL。SQLite 与 MySQL 各保留一份完整的 dbmate 初始化基线：

- `migrations/sqlite/202611070001_initial_schema.sql`
- `migrations/mysql/202611070001_initial_schema.sql`

此前每种数据库的 38 份迁移已合并并删除。基线直接定义表、字段、约束、索引和必要单例，不执行旧迁移链的转换。它适用于空数据库，不提供更早开发版本的升级路径；后续在此基线上新增迁移，不修改已部署的基线。

两种方言的 `202611080001_background_tasks.sql` 创建任务概览与明细快照，`202611090001_background_task_batches.sql` 增加独立批次状态、共享任务关系及扫描处理范围，并导入已确认的旧 parent 关系。应用启动依次应用基线和增量迁移，`schema_migrations` 记录 `202611070001`、`202611080001`、`202611090001`；已经部署基线的数据库只应用新版本。各增量 down 移除对应扩展，原有曲库和无关任务保留；更早任务增量 down 移除任务中心快照，原曲库和业务任务保留；初始化基线 down 仍会移除全部业务结构，只用于隔离验证库。

## 结构与初始值

业务表覆盖认证、媒体来源与解析、歌曲索引和扫描、元数据审核与分享、AI 与分类、歌手与图片、TV 与聚会、歌单、转码与音轨、缓存、真实播放统计及缺歌反馈。SQLite/MySQL 保留各自适用的文本、二进制、自增及索引定义；Go 不自动建表，业务 SQL 继续放在 模块内嵌 SQL。

- WebDAV 的文件大小和修改时间允许为空；扫描暂存与正式索引采用相同语义。
- 缓存策略直接默认 `HYBRID`，设置 revision 从 `0` 开始，高/低水位为 `90/75`。
- 歌曲、播放记录、缓存索引、固定偏好及播放实例初始为空；播放统计单例直接为 `ready=1, phase=READY`，无需等待历史回填。
- 管理员仍由应用认证初始化流程创建及计算密码摘要，SQL 不预置密码、密钥、真实设备或媒体数据。
- 外键、唯一键、CHECK 与业务查询索引在首次建库时创建，回退按依赖逆序删除业务表。`down` 仅用于可丢弃的验证库，不由应用启动流程自动执行。

## 从零验证

手工从零启动可给 `SQLITE_PATH` 指定一个全新文件路径，或使用新的 Docker Compose 项目与其独立数据卷；不要用旧库验证这份基线。现有命名卷和实际数据库由使用者保留或另行处理，本次整理不删除它们。

连接及驱动选择 见[数据库策略](../docs/database-strategy.md)，账号与主密钥见[认证说明](../docs/authentication.md)。数据库、WAL/SHM、凭据和主密钥不得提交；切换驱动 不自动迁移数据。

## 洛雪下载增量迁移

两种方言的 `202611090003_lx_downloads.sql` 新增唯一目标/音源绑定单例、加密音源版本、目录缓存、下载批次和逐曲明细，以及长期来源记录，共 6 张表。媒体来源的 `useForLxDownloads` 由单例绑定推导，不增加重复布尔存储；事务写锁保护唯一绑定。活动请求与解析音质分别有可空唯一键，结束后释放；下载来源独立于记录保留，重扫按文件大小、修改时间沿用元数据。此增量 down 只移除下载表，不删除媒体文件、原曲库或既有任务表；不可在正式库中回退后声称仍能恢复下载状态。

## 伴奏配方增量迁移

`202611090002_audio_separation_profiles.sql` 为 SQLite/MySQL 增加任务/批次 recipe_json 和 media_audio_selection；不修改已部署初始基线。默认旧行按 LEGACY_DEMUCS/AAC 解释；新配方隔离缓存，当前版本按媒体指纹绑定。

`202611100002_music_platform_defaults.sql` 在 SQLite/MySQL 中将未修改的安装种子调整为启用网易云、QQ、酷狗、酷我、汽水五个平台，自动应用仍默认关闭；精确匹配初始值及其时间标记，不覆盖任何已保存的配置。回退同样仅还原未修改的种子。

## 歌手封面批次增量

SQLite/MySQL 的 `202611100001_artist_artwork_batches.sql` 只新增封面批次及逐歌手结果两张表和队列/时间索引，不改变既有曲库、图片、账号或配置。请求标识唯一，选定平台和范围快照随批次保存；在途项重启后重新排队，图片仍以原 generation 保护。down 只移除这两张任务表，会丢失对应批次历史，应先完成任务，不在正式运行中回退。


`202611100003_media_library_workflows.sql` 在既有基线上新增共享系列、字段快照及版本基线、来源级导入任务与明细、持久入库请求，并为分享任务补充共享曲库版本。导入明细与歌曲资料按批事务提交，服务重启后继续；媒体核验独立于资料存储。两种数据库使用同一新迁移编号，基线未修改；该迁移 down 仅用于隔离验证，会移除本轮工作流和共享记录，不删除原媒体。


## 元数据标准增量迁移

SQLite/MySQL 成对新增 `202611110001_metadata_standard.sql`，保留已部署基线。新增正式文档及层级/搜索投影、位置、字段证据/差异/回执、资源与引用租约、不可变共享修订登记、共享身份映射、封面保存任务和旧共享资料迁移游标；媒体位置状态与 v4 任务信息独立保存。启动时旧媒体按“一文件一版本”分批登记，保留原 ID，不按同名合并；旧附件缺失只标记待恢复，不抹除文字资料。`metadata_document` 保存当前值和修订，不提供历史回滚。
down 只供隔离验证，会移除标准资料结构、证据和资源登记，不用于正式系统降级。持久附件目录必须与业务数据库配套备份，v4 资料包用于可移植曲库资料，不能替代账号/密钥和系统运行状态备份。

## 匹配参数默认值

SQLite/MySQL 的 `202611120003_matching_defaults.sql` 将未保存过的安装默认值更新为匹配阈值 80%、每首完成后等待 1～2 秒，自动应用仍默认关闭。升级和回退均精确检查旧参数与初始时间标记，不覆盖已保存的偏好。缓存预算由 Go 启动时根据缓存目录所在磁盘的可用空间初始化，默认 50 GiB，空间不足预算时取剩余空间的 80%；手动保存后的设置保持不变。

## NAS 共享收藏

SQLite/MySQL 成对新增 `202611140001_shared_favorites.sql`，只创建 `nas_favorite` 和 `nas_favorites_state`。收藏保存歌曲 ID、加入时间和辨认已移除歌曲所需的信息快照，同一状态行序列化批量写入，修订号每次有效变更只增加一次。没有媒体级联删除，也不导入旧手机或电视收藏。服务启动自动应用增量；down 仅用于隔离验证，会移除收藏集合，保留原曲库和媒体。
